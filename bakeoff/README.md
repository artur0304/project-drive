# Сравнение точности редактирования

Подготовлены четыре исходные фотографии и общий референс дисков. `cases.json` —
структурированный manifest, который AI-core проверяет и превращает в одинаковые
инструкции для каждого провайдера: замена дисков, снятие тонировки и изумрудная
глянцевая плёнка. Свободный prompt в manifest не хранится: его собирает общий
`instructions.ts`, поэтому сравнение не расходится по формулировкам.

Проверить набор без AI и без расходов:

```bash
npm --prefix HANDOFF-v2/ai-core-slice0 run bakeoff:validate
```

Валидатор проверяет существование изображений, формат операций, уникальность id и
показывает покрытие. Текущий набор намеренно имеет статус `NOT READY`: есть 4 из
минимальных 15 фото и нет отдельных кейсов `wheel_recolor`.

Проверить всю матрицу и создание отчётов только на mock:

```bash
npm --prefix HANDOFF-v2/ai-core-slice0 run bakeoff:mock-manifest
```

Команда создаёт 8 локальных результатов (4 фото × 2 mock-кандидата), но не
обращается к AI-провайдерам и не использует ключи.

## Ступенчатый bake-off

Каждый этап запускается отдельной командой. Между командами обязательны просмотр
`bakeoff_report.html`, слепая оценка и решение человека. Общей команды «запустить
всё» нет.

**Ступень 1 — живёт или нет:** 2 фото × 4 отдельные операции × 1 самый дешёвый
кандидат = ровно 8 вызовов. Безопасная проверка механики:

```bash
npm --prefix HANDOFF-v2/ai-core-slice0 run bakeoff:stage1:mock
```

После просмотра записать только прошедшие операции. **Ступень 2 — какая модель:**
3 фото × прошедшие операции × 2 кандидата. Пример безопасной проверки, если
прошли `wrap` и `tint`:

```powershell
$env:PROJECT_DRIVE_STAGE2_OPERATIONS="wrap,tint"
npm --prefix HANDOFF-v2/ai-core-slice0 run bakeoff:stage2:mock
```

Без `PROJECT_DRIVE_STAGE2_OPERATIONS` команда откажется работать. **Ступень 3 —
цена успешного результата** использует полный набор и заблокирована, пока manifest
не готов и человек после ступени 2 отдельно не выставил
`PROJECT_DRIVE_ALLOW_STAGE3=YES_AFTER_REVIEW`.

Mock-команды никогда не вызывают платный API. Будущий платный runner дополнительно
потребует свежего разрешения Артура, `PROJECT_DRIVE_ALLOW_PAID_AI=YES_FOR_THIS_RUN`
и будет ограничен общим ledger на $3. Разрешение одной ступени не разрешает следующую.

Платные команды уже подготовлены: `bakeoff:stage1`, `bakeoff:stage2` и
`bakeoff:stage3`. Запускать их сейчас запрещено. Даже при случайном запуске первая
команда остановится без `GEMINI_API_KEY` и свежего одноразового
`PROJECT_DRIVE_ALLOW_PAID_AI=YES_FOR_THIS_RUN`; вторая дополнительно требует список
прошедших операций, третья — готовый датасет и отдельный флаг после просмотра.
В каждом кандидате отключены автоматические ретраи, а пожизненный ledger ограничен $3.

Каждый прогон сохраняет `bakeoff_report.html`: исходное фото и результат рядом,
операция, кандидат, провайдер, стоимость, время и ошибка. Файл автономный и
открывается двойным кликом; картинки лежат в соседней папке `images/`.

## Фотографии

Новые снимки складывать в `bakeoff/new-photos/`. Понятная проверка без AI:

```bash
npm --prefix HANDOFF-v2/ai-core-slice0 run photos:check
```

Для ступени 1 уже достаточно двух из четырёх имеющихся фото. Для полного теста
нужны ещё 11, в том числе снимки в тени, сзади и с крупно видимыми дисками.

Статус: API-запуски не выполнены. Переменные OPENAI_API_KEY, GEMINI_API_KEY, GOOGLE_API_KEY и BFL_API_KEY отсутствуют в текущем процессе. Встроенный imagegen не предоставляет выбор этих трёх провайдеров.

Предыдущие четыре изображения в output/imagegen — отдельная проба встроенного инструмента; они не доказывают результаты какого-либо именованного API-моделя.

Оценка каждого результата: точность рисунка дисков; сохранность геометрии машины; отсутствие изменений фона и соседних машин; корректность прозрачности стёкол; точность цвета и границ плёнки. Салон за непрозрачным стеклом нельзя считать восстановленным по оригиналу.

Любой другой рисунок спиц означает провал замены дисков, даже если изображение
красиво. Результаты сравнивать без названий моделей. Harness сохраняет отдельный
слепой scoring-шаблон и `bakeoff_blind_key.json`; ключ нельзя открывать до
завершения ручной оценки. Фактическая модель, длительность, стоимость и ошибки
остаются в техническом отчёте. Для диагностики провала комбинированного задания
затем проверить операции по отдельности. Четыре фотографии не заменяют итоговый
bake-off на 15–20 фото.

Перед запуском нужны доступ к API, проверка актуальных моделей и тарифов, а также согласованный потолок затрат. Не хранить секретные ключи в этом файле или в cases.json.
