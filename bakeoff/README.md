# Сравнение точности редактирования

Подготовлены четыре исходные фотографии и общий референс дисков. `cases.json` —
структурированный manifest, который AI-core проверяет и превращает в одинаковые
инструкции для каждого провайдера: замена дисков, снятие тонировки и изумрудная
глянцевая плёнка. Свободный prompt в manifest не хранится: его собирает общий
`instructions.ts`, поэтому сравнение не расходится по формулировкам.

Проверить набор без AI и без расходов:

```bash
npm --prefix HANDOFF-v2/ai-core-slice0 run bakeoff:validate
```

Валидатор проверяет существование изображений, формат операций, уникальность id и
показывает покрытие. Текущий набор намеренно имеет статус `NOT READY`: есть 4 из
минимальных 15 фото и нет отдельных кейсов `wheel_recolor`.

Статус: API-запуски не выполнены. Переменные OPENAI_API_KEY, GEMINI_API_KEY, GOOGLE_API_KEY и BFL_API_KEY отсутствуют в текущем процессе. Встроенный imagegen не предоставляет выбор этих трёх провайдеров.

Предыдущие четыре изображения в output/imagegen — отдельная проба встроенного инструмента; они не доказывают результаты какого-либо именованного API-моделя.

Оценка каждого результата: точность рисунка дисков; сохранность геометрии машины; отсутствие изменений фона и соседних машин; корректность прозрачности стёкол; точность цвета и границ плёнки. Салон за непрозрачным стеклом нельзя считать восстановленным по оригиналу.

Любой другой рисунок спиц означает провал замены дисков, даже если изображение
красиво. Результаты сравнивать без названий моделей. Harness сохраняет отдельный
слепой scoring-шаблон и `bakeoff_blind_key.json`; ключ нельзя открывать до
завершения ручной оценки. Фактическая модель, длительность, стоимость и ошибки
остаются в техническом отчёте. Для диагностики провала комбинированного задания
затем проверить операции по отдельности. Четыре фотографии не заменяют итоговый
bake-off на 15–20 фото.

Перед запуском нужны доступ к API, проверка актуальных моделей и тарифов, а также согласованный потолок затрат. Не хранить секретные ключи в этом файле или в cases.json.
