# Project Drive — backend (шаг 1: фундамент)

Первый кирпич серверной части: **база данных + доступ к ней + маленький API-сервер.**
Работает БЕЗ установки чего-либо (используется встроенная в Node база SQLite).
Пока БЕЗ входа/паролей, БЕЗ оплаты, БЕЗ AI — их добавим следующими шагами.

## Что внутри
- `schema.sql` — структура таблиц (пользователи, проекты, версии, кошелёк, история кредитов).
- `db.mjs` — понятные функции работы с базой (создать пользователя, начислить/списать кредиты…).
- `auth.mjs` — вход и регистрация по почте+паролю (пароль хранится отпечатком, выдаются "пропуска").
- `server.mjs` — маленький веб-сервер (API), через который сайт общается с базой.
- `test.mjs` — самопроверка базы.
- `test-auth.mjs` — самопроверка входа.
- `projectdrive.db` — сам файл базы (создастся автоматически; в git его не кладём).

## Как запустить у себя (по шагам)
1. Поставь **Node.js 22+** (nodejs.org). Проверить: в терминале `node --version`.
2. Открой папку `backend` в терминале.
3. Проверить, что база работает:
   ```
   node --experimental-sqlite test.mjs
   ```
   Должен появиться отчёт с ✅ в конце.
4. Запустить сервер:
   ```
   node --experimental-sqlite server.mjs
   ```
   Откроется на http://localhost:3000
5. Проверить в браузере: открой http://localhost:3000/api/health — должно показать `{"ok":true}`.

## Что уже умеет API
Публичные:
- `GET  /api/health` — сервер жив
- `POST /api/auth/register` `{email,password,name}` — регистрация (пароль хранится отпечатком)
- `POST /api/auth/login` `{email,password}` — вход, возвращает "пропуск" (token)

Только для вошедших (нужен заголовок `Authorization: Bearer <token>`):
- `GET  /api/auth/me` — кто я
- `POST /api/auth/logout` — выход
- `POST /api/projects` `{name,vehicleMake,vehicleModel}` — создать свой проект (машину)
- `GET  /api/projects` — только МОИ проекты
- `PATCH /api/projects/:id` `{name}` — переименовать свой проект
- `GET  /api/versions?projectId=…` — версии моего проекта (чужой отдаст 404)
- `POST /api/versions/:id/report` `{reason,note}` — отправить свою версию на ручную проверку
- `GET  /api/wallet` — мой баланс кредитов
- `GET  /api/wallet/transactions` — моя история начислений и списаний
- `POST /api/wallet/add` `{amount,reason}` — пополнить СВОЙ баланс (только для разработки; в проде — по факту оплаты)
- `POST /api/upload?projectId=…` — загрузить фото машины (JPG/PNG/WEBP/HEIC до 20 МБ); сервер нормализует его в JPEG без EXIF/GPS
- `GET  /uploads/<файл>` — посмотреть загруженное (ТОЛЬКО для локальной разработки; в проде файлы приватные)
- `GET  /api/packs` — список пакетов кредитов (публично, для страницы Credits)
- `POST /api/checkout` `{packId}` — создать заказ на пакет; возвращает ссылку оплаты (сейчас заглушка)
- `POST /api/webhook/payment` `{orderId}` — платёжка сообщает "оплата прошла" → начисляем кредиты (идемпотентно)
- `POST /api/generate` `{projectId, operations}` — сгенерировать вариант: сервер считает цену,
  списывает кредиты, зовёт AI (пока ЗАГЛУШКА), сохраняет версию; при сбое кредиты возвращаются

Пример загрузки (curl):
```
curl -X POST "http://localhost:3000/api/upload?projectId=ВАШ_ID" \
     -H "Authorization: Bearer ВАШ_ТОКЕН" -H "Content-Type: image/jpeg" \
     --data-binary "@my-car.jpg"
```

Важно: проекты и кошелёк привязаны к вошедшему пользователю. `userId` в запросах
больше НЕ передаётся — сервер берёт его из "пропуска", поэтому нельзя запросить чужое.

## Заметки для Codex (важно для продолжения)
- **База сейчас SQLite** (файл, ноль настройки — удобно для локальной разработки и обучения).
  По плану проекта в проде — **PostgreSQL**. Функции в `db.mjs` написаны так, чтобы при
  переходе менялось только их тело, а названия и возвращаемые данные оставались теми же.
- **Сервер сейчас на голом `node:http`** (учебный, минимальный). По плану проекта фронт —
  **Next.js**, и API логичнее перенести в его API-routes. Логику каждого маршрута можно
  перенести 1:1, вызовы к `db.mjs` не меняются.
- Пока каркасно (нужен реальный провайдер): **оплата**. Логика заказ→оплата→начисление
  кредитов готова и идемпотентна, но провайдер — заглушка. В проде: в `/api/checkout`
  создавать checkout у merchant-of-record (Lemon Squeezy/Paddle) и возвращать его URL;
  в `/api/webhook/payment` ОБЯЗАТЕЛЬНО проверять подпись вебхука (иначе любой сможет
  "начислить" себе кредиты) — место помечено TODO(prod).
- **Генерация замкнута на ЗАГЛУШКЕ (mock)**: цена считается на сервере, кредиты списываются
  до вызова AI, версия сохраняется, при сбое кредиты возвращаются, при нехватке — отказ (см. `generation.mjs`).
  В проде: заменить `mockGenerate()` на реальный AI из папки `slice0` (адаптер Gemini/Nano Banana).
  Подключается когда решится вопрос с кредитами Google — интерфейс (вход/выход) тот же.
- Файл базы `projectdrive.db`, папку `uploads/`, `node_modules/` и `.env` в git НЕ коммитить.
- **Загрузка фото:** `sharp` применяет EXIF-ориентацию, ограничивает большую
  сторону 4096px, конвертирует файл в JPEG и удаляет EXIF/GPS. Некоторые варианты
  HEIC могут не поддерживаться системной сборкой; в этом случае API возвращает 422
  (место помечено в `server.mjs` как TODO(prod)), хранить в S3-совместимом хранилище (R2),
  В проде нужно отдавать файлы по временным (signed) ссылкам, а не свободно через `/uploads/`.
  Папку `uploads/` и файл базы `projectdrive.db` в git НЕ коммитить.
- Баланс кредитов НИКОГДА не уходит в минус — это проверяется в `spendCredits` (главная защита бюджета).
