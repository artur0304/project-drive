# Project Drive — backend (шаг 1: фундамент)

Первый кирпич серверной части: **база данных + доступ к ней + маленький API-сервер.**
Работает БЕЗ установки чего-либо (используется встроенная в Node база SQLite).
Пока БЕЗ входа/паролей, БЕЗ оплаты, БЕЗ AI — их добавим следующими шагами.

## Что внутри
- `schema.sql` — структура таблиц (пользователи, проекты, версии, кошелёк, история кредитов).
- `migrations/` — последовательные изменения схемы, включая масштабируемый каталог дисков.
- `db.mjs` — понятные функции работы с базой (создать пользователя, начислить/списать кредиты…).
- `auth.mjs` — вход и регистрация по почте+паролю (пароль хранится отпечатком, выдаются "пропуска").
- `server.mjs` — маленький веб-сервер (API), через который сайт общается с базой.
- `test.mjs` — самопроверка базы.
- `test-auth.mjs` — самопроверка входа.
- `test-generation.mjs` — цена, нехватка средств, возврат и успешное списание.
- `test-image-normalization.mjs` — применение ориентации и удаление метаданных.
- `test-object-storage.mjs` — единый слой файлов, запрет traversal и read-only каталога.
- `test-wheel-catalog.mjs` — пагинация, фильтры, избранное, recent и юридический publish-guard.
- `test-wheel-admin.mjs` — загрузка безопасного reference и публикация через админку.
- `test-server-security.mjs` — HTTP-проверка закрытых legacy-маршрутов и безопасных имён uploads.
- `test-ownership.mjs` — HTTP-проверка изоляции проектов, версий, uploads, генерации и жалоб между двумя пользователями.
- `scripts/seed-credits.mjs` — ручное локальное начисление тестовых кредитов.
- `projectdrive.db` — сам файл базы (создастся автоматически; в git его не кладём).

## Как запустить у себя (по шагам)
1. Поставь **Node.js 22+** (nodejs.org). Проверить: в терминале `node --version`.
2. Открой папку `backend` в терминале.
3. Проверить, что база работает:
   ```
   npm test
   ```
   Должен появиться отчёт с ✅ в конце.
4. Запустить сервер:
   ```
   node --experimental-sqlite --env-file=.env server.mjs
   ```
   Откроется на http://localhost:3000
5. Интерфейс открывается на http://localhost:3001. Если открыть корень backend
   http://localhost:3000, он сам перенаправит туда. Проверка API доступна на
   http://localhost:3000/api/health — должно показать `{"ok":true}`.

## Защита генерации от зависаний

- Списание кредита и создание `pending`-задания происходят одной транзакцией.
- При штатном успехе задание получает статус `done`, при ошибке — `failed` и кредит возвращается.
- При аварийной остановке сервер на следующем запуске возвращает кредиты за старые
  `pending`-задания. По умолчанию старыми считаются задания старше 10 минут;
  порог задаётся `PROJECT_DRIVE_PENDING_JOB_RECOVERY_MINUTES`.
- Вызов fal ограничен 90 секундами (`PROJECT_DRIVE_FAL_TIMEOUT_MS`). Если запрос
  уже отправлен провайдеру, SpendGuard консервативно учитывает возможные $0.08,
  а внутренний кредит пользователя возвращается.

## Что уже умеет API
Публичные:
- `GET  /api/health` — сервер жив
- `GET  /api/pricing` — модель цен `{ creditsPerPass, pricingVersion, rule }`; 1 кредит = 1 проход AI
- `GET  /api/wheels` — каталог с `q`, `brand`, `kind`, `diameter`, `finish`, `color`, `cursor`, `limit`
- `POST /api/auth/register` `{email,password,name}` — регистрация (пароль хранится отпечатком)
- `POST /api/auth/login` `{email,password}` — вход, возвращает "пропуск" (token)

Только для вошедших (нужен заголовок `Authorization: Bearer <token>`):
- `GET  /api/auth/me` — кто я
- `POST /api/auth/logout` — выход
- `POST /api/projects` `{name,vehicleMake,vehicleModel}` — создать свой проект (машину)
- `GET  /api/projects` — только МОИ проекты
- `PATCH /api/projects/:id` `{name}` — переименовать свой проект
- `GET  /api/versions?projectId=…` — версии моего проекта (чужой отдаст 404)
- `GET  /api/versions/:id` — одна своя версия для постоянной ссылки результата
- `POST /api/versions/:id/report` `{reason,note}` — отправить свою версию на ручную проверку
- `GET  /api/wallet` — мой баланс кредитов
- `GET  /api/wallet/transactions` — моя история начислений и списаний
- `POST /api/wheels/:id/favorite`, `GET /api/wheels/favorites` — избранное
- `POST /api/wheels/:id/view`, `GET /api/wheels/recent` — недавно просмотренные
- `POST /api/upload?projectId=…` — загрузить фото машины (JPG/PNG/WEBP/HEIC до 20 МБ); сервер нормализует его в JPEG без EXIF/GPS
- `GET  /uploads/<UUID>.jpg` — посмотреть созданный сервером JPEG (ТОЛЬКО для локальной разработки; в проде файлы приватные)
- `GET  /api/packs` — список пакетов кредитов (публично, для страницы Credits)
- `POST /api/checkout` `{packId}` — каркас заказа; по умолчанию отключён и отвечает `503`
- `POST /api/webhook/payment` `{orderId}` — локальный каркас webhook; по умолчанию
  скрыт за `404`, а в mock-режиме дополнительно отвергает не-loopback запросы
- `GET /api/catalog/customization` — активные каталоги плёнки, тонировки и цветов дисков без внутренних prompt-фрагментов
- `POST /api/waitlist` `{email}` — публичная запись в лист ожидания беты
- `POST /api/invites/redeem` `{code}` — активировать инвайт-код (нужен вход), атомарно начисляет генерации
- `POST /api/admin/invites` `{code, credits, maxUses, note}` / `GET /api/admin/invites` — создать/посмотреть коды
- `POST /api/admin/waitlist/invite` `{email, credits}` — создать персональный код для заявки из листа ожидания
- `POST /api/generate` `{projectId, operations}` — сгенерировать вариант: сервер считает цену (1 кредит = 1 проход AI: все простые правки = 1, замена дисков по фото = ещё 1),
  списывает кредиты, в `mock` использует заглушку, а в явно включённом `live` вызывает fal.ai;
  при сбое или практически неизменившемся результате кредиты возвращаются

Generation Planner объединяет плёнку, тонировку и перекраску дисков в один вызов.
Точная замена дисков с reference выполняется последним отдельным шагом. Если он
не проходит, успешная первая часть сохраняется со статусом `partial`, а кредиты
за неудавшийся и невыполненные шаги возвращаются. Страница результата явно
показывает частичный статус, фактическое списание и запланированную стоимость.

Перед списанием `/api/generate` проверяет структуру операций: допускаются одна
плёнка, одна тонировка и одна операция с дисками. Неизвестные, повторные и
неполные операции получают `400`; проект без фотографии получает `409`. Тестовый
`forceFail` доступен только при прямом вызове внутренней функции и исключён из HTTP.
Если провайдер выбрасывает исключение или готовую версию не удаётся записать в
базу, сервер возвращает ошибку и отдельной транзакцией восстанавливает списанные
кредиты. Эти два сценария входят в автоматический тест денежной цепочки.

Email сохраняется в нижнем регистре и сравнивается без учёта регистра. Локальная
сессия действует 30 дней; просроченный токен удаляется при следующей проверке.
После пяти неудачных входов для одной связки IP + email сервер на 15 минут
возвращает `429` и заголовок `Retry-After`; успешный вход очищает счётчик.
Обычные JSON-запросы ограничены 64 КБ: повреждённый JSON получает `400`, слишком
большой — `413`. Для фотографий действует отдельный лимит 20 МБ.
JSON-ответы помечены `Cache-Control: no-store`, а все ответы запрещают MIME-sniffing.
Локальные изображения дополнительно ограничены политикой `same-origin`.

Checkout и платёжный webhook по умолчанию выключены. Пока настоящий провайдер не
выбран, `POST /api/checkout` отвечает `503`, а webhook скрыт за `404`. Переменная
`PROJECT_DRIVE_ENABLE_MOCK_PAYMENTS=1` существует только для отдельной локальной
проверки каркаса и не должна включаться в обычном запуске.

## fal.ai / Nano Banana 2

Реальный серверный адаптер использует только `fal-ai/nano-banana-2/edit` через
официальный пакет `@fal-ai/client`. По умолчанию `PROJECT_DRIVE_AI_MODE=mock`,
поэтому локальный запуск и тесты не тратят деньги. В `live` нужны `FAL_KEY` и
catalog id каждой выбранной опции. Ключ остаётся только в `.env` backend.

Перед каждым платным вызовом `SpendGuard` резервирует $0.08 в локальном журнале.
Лимиты по умолчанию: $5 за всё время проекта, $2 в день и 6 попыток в час на
аккаунт/IP. Референс диска загружается после фото машины и его fal URL кэшируется.
Одинаковый исходник + одинаковые option id + версия prompt возвращают сохранённую
версию без нового вызова и без нового списания. Порог защиты от неизменённого
результата задаётся `PROJECT_DRIVE_MIN_IMAGE_DIFFERENCE`.

## Админка каталога

Задай `PROJECT_DRIVE_ADMIN_EMAILS=owner@example.com` перед запуском backend и
войди этим email. Интерфейс находится на <http://127.0.0.1:3001/admin>.
Он умеет создавать скрытые варианты, импортировать до 500 CSV-строк, загружать
reference, скрывать/публиковать диски, видеть AI jobs и аудит, корректировать
локальные кредиты с обязательной причиной. Публикация блокируется без источника,
основания прав и двух reference: front + ¾. Upload принимает только прозрачный
квадратный PNG/WebP до 10 МБ, очищает метаданные и ограничивает размер 1024×1024.

Формат CSV использует названия полей API: `brand,model,sizeLabel,diameter,color,finish,rightsSource,rightsBasis`.
Дополнительно допустимы `isOem,supplier,priceCents,affiliateLink,popularity,boltPattern,offset,centerBore`.
OEM-скрейпинг и публикация изображений без подтверждённых прав запрещены.

## Заметки для Codex (важно для продолжения)
- **База сейчас SQLite** (файл, ноль настройки — удобно для локальной разработки и обучения).
  По плану проекта в проде — **PostgreSQL**. Функции в `db.mjs` написаны так, чтобы при
  переходе менялось только их тело, а названия и возвращаемые данные оставались теми же.
- **Сервер сейчас на голом `node:http`** (учебный, минимальный). По плану проекта фронт —
  **Next.js**, и API логичнее перенести в его API-routes. Логику каждого маршрута можно
  перенести 1:1, вызовы к `db.mjs` не меняются.
- Пока каркасно (нужен реальный провайдер): **оплата**. Логика заказ→оплата→начисление
  кредитов готова и идемпотентна, но провайдер — заглушка. В проде: в `/api/checkout`
  создавать checkout у merchant-of-record (Lemon Squeezy/Paddle) и возвращать его URL;
  в `/api/webhook/payment` ОБЯЗАТЕЛЬНО проверять подпись webhook. До подключения
  провайдера весь backend привязан к `127.0.0.1`, а webhook имеет отдельную
  loopback-проверку, поэтому снаружи он недоступен.
- **Генерация замкнута на ЗАГЛУШКЕ (mock)**: цена считается на сервере, кредиты списываются
  до вызова AI, версия сохраняется, при сбое кредиты возвращаются, при нехватке — отказ (см. `generation.mjs`).
  В проде: заменить `mockGenerate()` на реальный AI из папки `slice0` (адаптер Gemini/Nano Banana).
  Подключается когда решится вопрос с кредитами Google — интерфейс (вход/выход) тот же.
- Файл базы `projectdrive.db`, папку `uploads/`, `node_modules/` и `.env` в git НЕ коммитить.
- **Загрузка фото:** `sharp` применяет EXIF-ориентацию, ограничивает большую
  сторону 4096px, конвертирует файл в JPEG и удаляет EXIF/GPS. Некоторые варианты
  HEIC могут не поддерживаться системной сборкой; в этом случае API возвращает 422
  (место помечено в `server.mjs` как TODO(prod)), хранить в S3-совместимом хранилище (R2),
  В проде нужно отдавать файлы по временным (signed) ссылкам, а не свободно через `/uploads/`.
  Папку `uploads/` и файл базы `projectdrive.db` в git НЕ коммитить.
- Баланс кредитов НИКОГДА не уходит в минус — это проверяется в `spendCredits` (главная защита бюджета).
- SQLite запускается с `foreign_keys = ON`. Индексы покрывают Garage, версии,
  исходники, журнал кредитов, сессии, заказы и очередь жалоб; каскадное удаление
  связанных записей проверяется автоматически.
