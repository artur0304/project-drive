# Project Drive — варианты будущего деплоя

> Подготовительный документ. Ничего не развёрнуто и не оплачено. Перед запуском
> нужно заново проверить актуальные цены, регионы и условия каждого сервиса.

## Рекомендуемая первая схема

- **Web:** Next.js на Vercel или одном Node-хосте вместе с API.
- **Backend:** постоянный Node-процесс на Railway/Render/Fly.io либо VPS.
- **Database:** управляемый PostgreSQL в том же регионе, что backend.
- **Images:** приватный Cloudflare R2 или другое S3-совместимое хранилище.
- **AI:** fal.ai только с серверным `FAL_KEY` и существующим `SpendGuard`.

Для закрытой беты проще один Node-хост + управляемый PostgreSQL + R2. Это
уменьшает число движущихся частей и сохраняет возможность разнести сервисы позже.

## Что уже подготовлено

- Все операции с изображениями проходят через `backend/object-storage.mjs`.
- Локальный адаптер сохраняет прежние URL `/uploads/...` и `/wheel-uploads/...`.
- Бизнес-логика базы сосредоточена в `db.mjs`; HTTP-маршруты не выполняют SQL.
- Миграции пронумерованы, включая durable `generation_jobs`.
- Секреты читаются только из `backend/.env`; `.env` не попадает в Git.

## Что сделать перед настоящим деплоем

### PostgreSQL

1. Добавить отдельный `postgres-db.mjs` с теми же экспортами, что `db.mjs`.
2. Перевести синхронные функции SQLite на `async` и обновить места вызова.
3. Переписать `?` placeholders на `$1, $2…`, `INSERT OR IGNORE` на
   `ON CONFLICT`, а SQLite PRAGMA убрать.
4. Выполнить миграции в транзакциях и хранить `schema_migrations`.
5. Проверить атомарно: инвайты, оплату, `beginGenerationJob`, recovery и админские
   корректировки кредитов.
6. Сделать одноразовый экспорт SQLite → PostgreSQL и сверить количество строк,
   балансы кошельков и внешние ключи.

Полный перенос сейчас намеренно не включён: для него нужен выбранный PostgreSQL,
строка подключения и резервная копия рабочей SQLite. До выбора хоста локальный
SQLite остаётся источником правды.

### R2/S3

Новый адаптер должен реализовать `ensureReady`, `put`, `get`, `exists` и возвращать
неугадываемые object keys. Исходники машин и результаты держать приватными;
браузеру выдавать короткоживущие signed URL. Каталог дисков можно отдавать через
CDN только после publish-guard и подтверждения прав.

Будущие переменные: `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`,
`S3_SECRET_ACCESS_KEY`. Они допустимы только в секретах хоста, не в Git.

## Проверка перед открытием беты

- HTTPS, безопасные cookies/сессии, CORS только с домена продукта.
- PostgreSQL backup и проверенное восстановление.
- R2 lifecycle/retention и удаление данных по запросу пользователя.
- fal timeout, SpendGuard, rate limit и pending-job recovery включены.
- Оплата выключена до отдельного решения Артура.
- Privacy/Terms проверены юристом и содержат реальные контакты и сроки хранения.
