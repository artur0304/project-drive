# Project Drive — Next.js-каркас

Первый безопасный шаг соединения готового дизайна с локальным бэкендом.

- Готовые HTML-прототипы лежат в `public/prototype/` и пока показываются без
  визуальных изменений.
- Next.js принимает браузерные запросы к `/api/*` и передаёт их локальному
  бэкенду на `127.0.0.1:3000`.
- Запросы к `/uploads/*` передаются туда же, чтобы загруженные фотографии были
  доступны через один адрес приложения.
- Реальная AI-генерация не подключена. Бэкенд продолжает использовать бесплатную
  заглушку `mockGenerate()`.

## Локальный запуск

1. Запустить бэкенд на порту 3000.
2. В этой папке выполнить `npm run dev` переносной Node.js 22.
3. Открыть <http://127.0.0.1:3001>.

Экран Upload уже перенесён в React: он проверяет формат и размер, показывает
настоящий предпросмотр и временно хранит фото гостя в IndexedDB браузера.
Регистрация здесь намеренно не добавлена — по утверждённому пользовательскому пути
она появляется только перед первой генерацией.

Configurator тоже перенесён в React. Он читает сохранённое фото из IndexedDB,
показывает его без изменений, хранит draft в localStorage, считает стоимость и
сохраняет выбор после перезагрузки. Замена и перекраска дисков взаимоисключаются.

Вкладка Wheels читает каталог через API, ищет и фильтрует на сервере, загружает
страницы курсором и виртуализирует строки карточек. Доступны Popular, Favorites и
Recent. На телефоне фото остаётся сверху, а настройки открываются bottom sheet с
режимами Peek, Half и Full. Админка каталога доступна на `/admin` только email из
`PROJECT_DRIVE_ADMIN_EMAILS`.

Auth gate подключён к локальным регистрации и входу. После успешной авторизации
приложение создаёт проект, загружает фото в локальный backend, начисляет только
демонстрационные dev-кредиты и вызывает бесплатный `mockGenerate()`. Результат и
before/after открываются на React-странице `/result`; версия сохраняется в SQLite.

Реальные AI-вызовы по-прежнему заблокированы; каталог и мобильный интерфейс
полностью работают на локальных данных и mock-генерации.
